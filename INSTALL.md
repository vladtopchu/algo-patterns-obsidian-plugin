# Установка Algo Patterns

Готовая сборка находится в `dist/algo-patterns-trainer/`. Для обычной установки Node.js и сборка исходников не нужны.

## 1. Скопируйте плагин

Откройте папку своего **vault** — ту, где находятся ваши заметки и папка `.obsidian`. Создайте внутри:

```text
<ваш-vault>/.obsidian/plugins/algo-patterns-trainer/
```

Скопируйте туда три файла из `dist/algo-patterns-trainer/`:

```text
main.js
manifest.json
styles.css
```

Правильная структура:

```text
ваш-vault/
  .obsidian/
    plugins/
      algo-patterns-trainer/
        main.js
        manifest.json
        styles.css
```

Не добавляйте ещё одну вложенную папку `algo-patterns-trainer`. На macOS скрытые файлы можно показать сочетанием **Cmd + Shift + .** в Finder.

Альтернатива через терминал, если установлен Node.js:

```sh
cd /Users/vlad/dev/algo_patterns_obsidian_plugin
node scripts/install.mjs "/полный/путь/к/вашему/vault"
```

Скрипт копирует только три файла плагина. Он не включает плагин автоматически и не меняет каталог или историю попыток.

## 2. Включите плагин

1. Откройте Obsidian **1.8.7 или новее**.
2. Откройте **Settings → Community plugins** (Настройки → Сторонние плагины).
3. Если включён Restricted mode, разрешите сторонние плагины.
4. Перезапустите Obsidian, если Algo Patterns ещё не появился в списке.
5. Включите **Algo Patterns**.
6. Откройте палитру команд **Cmd + P** и выберите **Algo Patterns: Открыть тренажёр**. Также доступна кнопка с иконкой мозга на левой панели.

Плагин устанавливается вручную; публикации в каталоге Community plugins нет.

## Настройки и хранение прогресса

Откройте **Settings → Algo Patterns**: здесь задаются папка данных, время на план, доля новых задач, скрытие паттерна и короткие проверки. Те же параметры доступны в тренажёре.

Все изменения автоматически сохраняются в `<vault>/_algo_patterns/tracker.json`. Файл содержит каталог, историю попыток, расписания повторений, настройки практики и активный таймер. Текущий путь виден внизу экрана тренажёра и на вкладке «Данные».

Папка по умолчанию — `_algo_patterns`. Её можно изменить в настройках или на вкладке «Данные». При сохранении вся папка, включая `Backups/` и `Tasks/`, переносится в новый свободный путь. Путь хранится в стандартном файле настроек плагина `.obsidian/plugins/algo-patterns-trainer/data.json`. При обновлении прежняя папка `Algo Patterns/` автоматически переносится в `_algo_patterns/`, если новый путь свободен. Если он занят, плагин продолжает работать со старой базой и показывает уведомление.

## 3. Загрузите задачи

На пустом экране нажмите **«Загрузить встроенный каталог»**, проверьте предварительный просмотр и нажмите **«Импортировать»**.

В сборку включён каталог из предоставленного `algo_patterns.numbers`: **15 тем, 94 паттерна, 413 уникальных задач**. Повторяющиеся задачи объединены, их связи с разными паттернами сохранены.

В исходнике отсутствовали уровни сложности и URL. Поэтому сложности установлены в **Unknown**, ссылки ведут на поиск LeetCode по ID. На экране **«Каталог → Изменить»** можно поставить Easy / Medium / Hard и прямую ссылку на условие.

Категоризация сохранена из таблицы и не проверена на методическую корректность. В трёх строках были лишние числа перед ID; отчёт находится в исходном проекте: `data/import-report.txt`.

Для другого каталога используйте кнопку **«Импорт каталога»**. Поддерживаются:

- CSV/TSV с колонками `topic,pattern,title,id,url,difficulty`;
- экспорт вашего Numbers с колонками `Pattern,Problems`;
- JSON каталога с `topics`, `patterns`, `problems`.

Файл `.numbers` непосредственно в плагине не открывается: в Numbers выберите **File → Export To → CSV**. Есть пример `data/example.csv`.

## 4. Первая практика

1. На экране **«Сегодня»** выберите тему, при необходимости конкретный паттерн и доступное время.
2. Нажмите **«Начать»** у задачи. Таймер будет сохранён сразу.
3. Нажмите **«Открыть LeetCode / условие»** и решайте в привычной среде.
4. Если воспользовались подсказкой, отметьте это в трекере.
5. Вернитесь в Obsidian → **«Завершить»**. Таймер остановится.
6. Укажите реальное активное время, способ решения и результат. При желании добавьте короткий разбор.
7. Нажмите **«Сохранить результат»** — история и расписание обновятся.

Если уже решили задачу вне трекера: **«Каталог → Внести результат»**. Задайте длительность вручную. Датой попытки станет момент сохранения; ввод результатов за прошлые даты в этой версии отсутствует.

Пауза исключает время отдыха. Таймер использует сохранённую отметку времени: закрытие окна или Obsidian само по себе его не останавливает. Длительность можно исправить перед сохранением. Отмена формы результата сохраняет попытку на паузе; отдельная кнопка «Отменить попытку» сбрасывает её без влияния на расписание.

## 5. Как устроены повторения

- Первое самостоятельное решение назначает повторение через 1 день.
- Последующие самостоятельные решения увеличивают интервал: **3 → 7 → 14 → 30 → 60 → 90 дней**.
- Подсказка, разбор готового решения или неудача сбрасывают интервал до **1 дня**.
- У каждой пары «задача — использованный паттерн» своё расписание.
- Полное решение и короткое воспроизведение подхода имеют независимые расписания. Короткая проверка никогда не засчитывается как полное решение.
- В **«Данные»** можно включить короткие проверки и скрытие паттерна при смешанной практике.
- При просрочке старые даты сохраняются, а план набирается в рамках указанного времени. Штрафов за пропуск нет.
- Можно исключить задачу из автоматической очереди через **«Каталог → Изменить»**.

Это прозрачная лестница интервалов, **не FSRS** и не оценка вероятности успешного решения. Алгоритм может быть заменён без потери журнала попыток.

Оценки длительности: Easy — 15 минут, Medium — 30, Hard — 45, Unknown — 30, короткая проверка — 5. После самостоятельных решений используется медиана последних пяти успешных полных попыток по той же задаче.

Время на экране «Сегодня» относится к **следующему плану**. После попытки план пересчитывается заново; общий дневной лимит и отдельный журнал сессий в версии 1.0 не ведутся. Соотношение нового и повторений приблизительное: оставшееся время заполняется задачами, которые помещаются в бюджет.

## 6. Где находятся данные

После первого включения создаётся:

```text
<vault>/_algo_patterns/tracker.json
```

Это основной файл: каталог, все попытки, расписания, настройки и текущий таймер. Не удаляйте его при обновлении плагина. Материалы доступны независимо от плагина: JSON читается любым текстовым редактором, Markdown-заметки создаются кнопкой «Заметка» в `_algo_patterns/Tasks/`.

Свойства созданной Markdown-заметки — снимок на момент создания; их ручное редактирование не меняет каталог. Журнал и каталог редактируются через плагин.

**«Данные → Создать резервную копию»** сохраняет полный JSON в `_algo_patterns/Backups/`. Перед повторным импортом и восстановлением копия создаётся автоматически. Для восстановления выберите полный JSON через **«Восстановить резервную копию»**. Обычный импорт JSON переносит только каталог, без истории.

При синхронизации двух устройств дайте файлам синхронизироваться перед началом практики. Одновременное редактирование базы с двух устройств не объединяется автоматически. Если файл был изменён извне, плагин остановит запись и предложит **«Перезагрузить базу»**; текущие изменения не затрут внешний файл. При повреждённом JSON он не создаёт пустую базу поверх данных.

## Обновление и удаление

Для обновления отключите плагин, замените `main.js`, `manifest.json`, `styles.css`, затем включите его. Файл `_algo_patterns/tracker.json` остаётся прежним. Чтобы удалить плагин, отключите его и удалите только папку `.obsidian/plugins/algo-patterns-trainer`; ваши данные и заметки останутся в vault.

## Сборка из исходников

Нужен Node.js 22 или новее:

```sh
cd /Users/vlad/dev/algo_patterns_obsidian_plugin
npm ci
npm run package
```

`npm run package` проверяет TypeScript, собирает `main.js`, запускает тесты и создаёт готовую папку в `dist/`. На macOS/Linux при наличии `zip` также создаётся архив `dist/algo-patterns-trainer-1.0.2.zip`.

Команды разработчика:

```sh
npm run dev       # пересборка при изменении исходников
npm test          # тесты логики, хранения и интерфейса
npm run build     # проверка типов и сборка
```

## Если что-то не работает

- **Плагин не виден:** проверьте путь и отсутствие лишнего уровня вложенности, затем перезапустите Obsidian.
- **Пустой план:** выберите тему, увеличьте бюджет или начните задачу вручную. Повторения появляются только после первой сохранённой попытки и наступления срока.
- **Ошибка импорта:** проверьте заголовки колонок и кавычки в CSV; используйте предварительный просмотр.
- **Не удалось открыть базу:** сохраните копию `tracker.json`, исправьте JSON или замените его сохранённой резервной копией при выключенном плагине, затем включите плагин.
- **Обновление не применилось:** выключите и включите плагин либо перезапустите Obsidian.

LeetCode API, автоматическая проверка кода и передача данных в AI-сервисы не используются. Плагин не отправляет каталог или результаты в сеть; внешние ссылки открываются по вашему действию.
